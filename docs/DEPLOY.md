# Выложить Ikigai на Vercel одной командой

Рядом с кодом уже лежит `vercel.json`: прямые ссылки вроде `/settings` открываются (запасной маршрут на `index.html`),
файлы с хешами в `/assets` кешируются навсегда, а `sw.js` и манифест всегда свежие. Остальное Vercel определяет сам
(Vite, команда `npm run build`, папка `dist`).

## Выложить

В терминале на этом Mac (вход в Vercel уже выполнен под `didariganto`):

```bash
cd ~/Desktop/ikigai && npx vercel deploy --prod --yes
```

Первый запуск создаст проект `ikigai` в области «didariganto's projects» и положит привязку в `.vercel/` (в git она не попадает).
В конце команда напечатает адрес вида `https://ikigai-xxxx.vercel.app`. Каждый следующий запуск обновляет сайт по тому же адресу.
Если вход слетел: `npx vercel login`.

## Проверить после выкладки

1. Адрес открывается, видно приветствие (в новом браузере — первый запуск с вопросом «Как тебя зовут?»).
2. Прямая ссылка `<адрес>/settings` открывается, а не даёт 404.
3. В браузере: инструменты разработчика → Application → Service Workers: воркер активен (установка как приложение доступна в меню браузера).

## Что важно знать

- Данные лежат в браузере каждого посетителя (IndexedDB). Публичный адрес не открывает ничьих данных, в том числе твоих: на другом устройстве приложение начнётся с чистого листа, пока не подключено облако.
- Облако и бот: когда пройдёшь `docs/SETUP.md`, в Vercel → Settings → Environment Variables добавь `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` и `VITE_TELEGRAM_BOT` и выложи заново.
- Автообновление от GitHub (каждый `git push` выкладывает сам): Vercel → проект → Settings → Git → Connect → `DIDARIGANTO/ikigai`. Работает после того, как код отправлен в репозиторий.
- Свой домен: Vercel → проект → Settings → Domains.
