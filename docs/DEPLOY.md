# Выложить Ikigai на Vercel одной командой

Рядом с кодом уже лежит `vercel.json`: прямые ссылки вроде `/settings` открываются (запасной маршрут на `index.html`),
файлы с хешами в `/assets` кешируются навсегда, а `sw.js` и манифест всегда свежие. Остальное Vercel определяет сам
(Vite, команда `npm run build`, папка `dist`).

## Выложить

В терминале на этом Mac, из папки проекта:

```bash
bash scripts/deploy-vercel.sh
```

Скрипт читает публичные настройки облака из `.env` (их делает `scripts/connect-telegram.sh`), при необходимости просит войти
в Vercel, создаёт проект `ikigai`, кладёт в него три переменные (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`,
`VITE_TELEGRAM_BOT`), убеждается, что задан пароль на сайт (если нет, спрашивает его: см. ниже), выкладывает сайт,
проверяет, что без пароля он и правда закрыт, и в конце печатает постоянный адрес (строка `Aliased`) и копирует его в буфер обмена.
Пароль вводится руками, поэтому запускать скрипт нужно в панели Terminal, а не строкой «!» в чате.
Открывать и вписывать в Supabase нужно именно его (вида `https://ikigai-xxxx.vercel.app`): длинный адрес самой выкладки с хешем
Vercel прячет за входом в свой аккаунт («Deployment Protection»), а постоянный адрес проекта открыт всем.
При создании проекта Vercel сам подключает репозиторий GitHub, если он есть: после этого каждый новый снимок в `main` выкладывается сам
(отключить: Vercel → проект → Settings → Git → Disconnect).
Секретный ключ Supabase он в сайт не пропустит: проверяет, что в `.env` лежит именно публичный.
Каждый следующий запуск обновляет сайт по тому же адресу. Проверка без сети и изменений: `DRY_RUN=1 bash scripts/deploy-vercel.sh`.

## После выкладки: сказать Supabase про новый адрес

Без этого письмо со ссылкой для входа будет вести не на сайт.
Supabase → проект `ikigai` → **Authentication** → **URL Configuration**:

1. **Site URL** — адрес сайта.
2. **Redirect URLs** → **Add URL** — адрес сайта с `/**` на конце (оставь и `http://localhost:5180/**` для работы на компьютере) → **Save**.

Дальше открыть сайт, войти по ссылке из письма и в **Настройки → Telegram** убедиться, что бот подключён (привязка хранится в облаке,
второй раз подключать не нужно).

## Сайт только для тебя

Сайт закрыт паролем целиком. Без пароля посторонний видит только окно «Закрытый сайт» с полем пароля: ни экрана входа, ни кода
приложения, ни его файлов ему не отдают. Устроено это так: Vercel перед каждым запросом вызывает файл `middleware.ts`
(логика в `gate/`), а он без пароля отвечает окном пароля (страницы) или ошибкой 401 (файлы).

- **Пароль задаёт `bash scripts/site-password.sh`** (в панели Terminal: пароль вводится руками, на экране не виден, не короче 10 знаков).
  Скрипт кладёт на Vercel две секретные переменные: `SITE_PASSWORD` (твой пароль) и `SITE_GATE_SECRET` (случайный ключ, которым
  подписывается вход; его никто не вводит и не видит). Прочитать их обратно нельзя ни в панели Vercel, ни командой. Новый пароль
  начинает действовать после следующей выкладки.
- **На каждом устройстве пароль спросят один раз** и запомнят на 90 дней (Safari предложит сохранить его в связке ключей).
  Внутри остаётся обычный вход по ссылке из письма. Ссылка из письма на устройстве, где пароль ещё не вводили, сначала покажет окно
  пароля, а потом откроет приложение: токен из адреса при этом не теряется.
- **Если пароль не задан, сайт закрыт для всех** (ответ 503 с подсказкой), а не открыт всем: забытая настройка не выставит его наружу.
  Лечится тем же скриптом и новой выкладкой.
- **Сменить пароль:** запустить скрипт ещё раз и выложить сайт заново. Старый пароль перестаёт открывать дверь новым устройствам.
  Устройства, где приложение уже стоит, открываются из своей копии в браузере и после смены пароля; чтобы вычеркнуть конкретное
  устройство, в нём нужно очистить данные сайта.
- Если сайт уже открывался на этом устройстве до появления пароля, браузер может показывать старую копию без запроса пароля, а новую
  версию не получать: обнови страницу жёстко (Cmd+Shift+R на компьютере; на телефоне — открой сайт во вкладке «Приватный доступ»
  или удали данные сайта в настройках браузера).
- Пароль закрывает только дверь сайта. Базу Supabase он не защищает: ей служит собственный вход и правила доступа, а доступ к самому
  Supabase идёт напрямую, мимо сайта. Поэтому регистрацию закрывай отдельно:

1. **Закрыть регистрацию.** После того как ты один раз вошёл, Supabase → **Authentication** → **Sign In / Providers** →
   **User Signups** → выключить **Allow new users to sign up**. Новых людей добавляешь только ты (Authentication → Users →
   Add user / Invite), существующие входят как раньше. Это важно и для бота: любой зарегистрированный мог бы привязать к нему свой Telegram и тратить твои платные ключи ИИ.
2. **Спрятать от поисковиков.** Уже сделано: `robots.txt`, метка `noindex` на странице и заголовок `X-Robots-Tag`.

Код при этом не публикуется: на Vercel он уходит командой с твоего компьютера (или из закрытого репозитория GitHub), исходники Vercel
по умолчанию никому не показывает. В браузер, как у любого сайта, отдаётся только готовая сжатая сборка, и только после пароля.
Репозиторий на GitHub отдельно: чтобы код был закрыт и там, сделай его приватным (Settings → Danger Zone → Change visibility
или `gh repo edit DIDARIGANTO/ikigai --visibility private --accept-visibility-change-consequences`). Vercel умеет выкладывать из приватного репозитория личного аккаунта; после перевода проверь, что выкладка по `git push` по-прежнему идёт.

## Что где лежит и что может утечь

| Что | Где лежит | Кто может прочитать |
| --- | --- | --- |
| Код сайта | GitHub, Vercel | Пока репозиторий публичный, код видят все; личных данных и секретных ключей в нём нет (перед каждой публикацией идёт скан). Закрывается переводом репозитория в приватный. |
| Твои записи (задачи, цели, заметки, долги…) | в браузере (локальный режим) или в базе Supabase (облачный режим) | В облаке только ты после входа: правила доступа базы (`auth.uid() = user_id`) не отдают чужие строки даже по публичному ключу. Технически базу может прочитать владелец проекта Supabase (ты) и сам Supabase: сквозного шифрования нет. |
| Ключи (Anthropic, Groq, токен бота, service role) | секреты Supabase и файл `.env` на твоём компьютере | Только ты. В GitHub и на Vercel не попадают (`.env` в `.gitignore` и `.vercelignore`); в сайт вшивается только публичный ключ Supabase, он по замыслу открыт и без входа ничего не читает. |
| Сообщения боту | Telegram → функция в Supabase → Anthropic (разбор текста) и Groq (голос) | Эти сервисы обрабатывают то, что ты написал боту. Бот отвечает только привязанному чату. Пароли и банковские данные ему не диктуй. |

Пароли от почты, банка и тому подобное в Ikigai не храни: заметки лежат в базе открытым текстом (защищённой, но не зашифрованной).
Для паролей есть менеджеры паролей (связка ключей iCloud и др.). Включи двухфакторную защиту на почте и в аккаунтах GitHub, Vercel и
Supabase: любой из них даёт доступ ко всему остальному.

## Проверить после выкладки

1. Адрес открывается, видно окно пароля «Закрытый сайт»; после пароля — экран входа (или приветствие, если облако не подключено).
2. Прямая ссылка `<адрес>/settings` открывается, а не даёт 404.
3. В браузере: инструменты разработчика → Application → Service Workers: воркер активен (установка как приложение доступна в меню браузера).

## Что важно знать

- В облачном режиме данные лежат в Supabase и открываются с любого твоего устройства после входа. Без облака они хранятся в браузере
  каждого посетителя (IndexedDB), и на другом устройстве приложение начнётся с чистого листа.
- Данные, накопленные в браузере в локальном режиме (адрес `localhost`), на сайт сами не переезжают: у сайта другое хранилище.
  Перенести их можно кнопкой **Настройки → Облако → «Перенести в облако»**, нажав её на том адресе, где данные лежат; после входа
  они появятся и на сайте.
- Автообновление от GitHub (каждый `git push` выкладывает сам): Vercel → проект → Settings → Git → Connect → `DIDARIGANTO/ikigai`.
  Работает после того, как код отправлен в репозиторий. Переменные из шага выше при этом уже лежат в проекте.
- Свой домен: Vercel → проект → Settings → Domains (и тогда добавь его в Supabase так же, как выше).
