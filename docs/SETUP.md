# Подключение Ikigai к облаку

Инструкция для владельца. Программировать не нужно — только нажимать кнопки и копировать текст.
Пройти всё можно за 20–30 минут.

Пока облако не подключено, приложение работает и так: данные лежат в браузере на одном
устройстве. Облако нужно, чтобы записи были на телефоне и на компьютере одновременно,
и чтобы позже заработал Telegram-бот.

Что понадобится:

- почта, к которой есть доступ;
- аккаунт GitHub — на шаге 4 я помогу загрузить туда код (это нужно для Vercel);
- 10 минут без спешки — на шаге 2 нужно скопировать длинный текст целиком.

---

## 1. Создать проект Supabase

Supabase — это база данных в интернете, где будут храниться записи.

1. Открыть <https://supabase.com> и нажать **Start your project**.
2. Войти через **Continue with GitHub** и разрешить доступ.
3. На странице проектов нажать **New project**.
4. Заполнить поля:
   - **Name** — `ikigai`;
   - **Database Password** — нажать **Generate a password** и сохранить пароль в надёжном месте
     (он понадобится редко, но восстановить его нельзя);
   - **Region** — `Central EU (Frankfurt)`;
   - **Pricing Plan** — `Free`.
5. Нажать **Create new project** и подождать 1–2 минуты, пока наверху не пропадёт надпись
   `Setting up project`.
6. В левом меню внизу открыть **Project Settings** → раздел **API**.
7. Скопировать два значения:
   - **Project URL** — адрес вида `https://abcdefgh.supabase.co`;
   - **Project API keys** → строка **anon** **public** — длинный ключ. Нажать на значок
     копирования справа от него.
8. В папке проекта на компьютере сделать копию файла `.env.example` и назвать её `.env`,
   затем вписать скопированное после знаков `=`:

   ```
   VITE_SUPABASE_URL=https://abcdefgh.supabase.co
   VITE_SUPABASE_ANON_KEY=вставить_сюда_ключ_anon_public
   ```

   Без пробелов вокруг `=` и без кавычек. Файл `.env` не попадает в GitHub — это нормально,
   те же две строки мы отдельно пропишем в Vercel на шаге 4.

> Ключ **anon public** можно показывать кому угодно — он безопасен. Ключ **service_role**
> с этой же страницы никому передавать нельзя и в `.env` он не нужен.

## 2. Создать таблицы (SQL)

1. В левом меню Supabase открыть **SQL Editor**.
2. Нажать **New query**.
3. Открыть в папке проекта файл `supabase/migrations/0001_init.sql`, выделить весь текст
   (Ctrl+A / ⌘+A), скопировать и вставить в окно редактора.
4. Нажать зелёную кнопку **Run** справа внизу (или Ctrl+Enter / ⌘+Enter).
5. Внизу должно появиться сообщение **Success. No rows returned**. Это значит, что таблицы созданы.
6. Проверить: в левом меню открыть **Table Editor** — в списке появятся таблицы
   `rows`, `bot_links`, `bot_drafts`, `sent_digests`, `ai_usage`.

Если случайно запустить этот скрипт второй раз, ничего не сломается: он написан так,
чтобы повторный запуск проходил без ошибок и не стирал данные.

## 3. Включить вход по ссылке из письма

Пароля в Ikigai нет: при входе на почту приходит письмо со ссылкой.

1. В левом меню открыть **Authentication** → вкладка **Providers** (в некоторых версиях
   интерфейса — **Sign In / Up**).
2. В списке найти **Email** и раскрыть его.
3. Проверить переключатели:
   - **Enable Email provider** — включён;
   - **Confirm email** — включён;
   - **Enable Email OTP** или **Magic Link** — включён;
   - **Enable Email Signup** — включён, иначе первый вход не создаст аккаунт.
4. Нажать **Save**.
5. Перейти в **Authentication** → **URL Configuration**.
6. В поле **Site URL** вписать адрес сайта. Пока сайта в интернете нет — `http://localhost:5173`;
   после шага 4 вернуться сюда и заменить на адрес с Vercel.
7. В поле **Redirect URLs** нажать **Add URL** и добавить оба адреса:
   `http://localhost:5173` и адрес с Vercel (когда он появится).
8. Нажать **Save changes**.

> Бесплатный почтовый отправитель Supabase ограничен несколькими письмами в час.
> Для одного владельца этого достаточно. Если письмо не пришло — проверить папку «Спам».

## 4. Выложить сайт на Vercel

Vercel бесплатно держит сайт в интернете и обновляет его после каждого изменения кода.

> Быстрый путь без GitHub — одна команда из терминала, см. `docs/DEPLOY.md`. Ниже — путь через GitHub: сайт обновляется сам после каждого `git push`.

1. Открыть <https://vercel.com> и нажать **Sign Up** → **Continue with GitHub**.
2. На главной странице нажать **Add New...** → **Project**.
3. В списке репозиториев найти `ikigai` и нажать **Import**.
4. Проверить, что определилось само:
   - **Framework Preset** — `Vite`;
   - **Build Command** — `npm run build`;
   - **Output Directory** — `dist`.
5. Раскрыть **Environment Variables** и добавить две переменные — те же, что в `.env`:
   - **Key** `VITE_SUPABASE_URL`, **Value** — адрес проекта Supabase;
   - **Key** `VITE_SUPABASE_ANON_KEY`, **Value** — ключ `anon public`.

   Каждую добавляют кнопкой **Add**.

   Сайт закрыт паролем (`middleware.ts`): без пароля на Vercel он отвечает «ещё не задан» всем, включая тебя. Пароль и ключ входа
   кладёт команда `bash scripts/site-password.sh` (см. `docs/DEPLOY.md`), её запускают после того, как проект на Vercel создан.
   Если тебе удобнее руками: добавить ещё две переменные, обе с пометкой **Sensitive** — `SITE_PASSWORD` (пароль) и
   `SITE_GATE_SECRET` (любые 64 случайных символа, например из команды `openssl rand -hex 32`).
6. Нажать **Deploy** и подождать 1–2 минуты до надписи **Congratulations**.
7. Нажать **Continue to Dashboard** и скопировать адрес сайта вида
   `https://ikigai-xxxx.vercel.app` (он написан вверху под заголовком **Domains**).
8. Вернуться в Supabase → **Authentication** → **URL Configuration** и вписать этот адрес
   в **Site URL** и в **Redirect URLs**, затем **Save changes**.

### Первый вход

1. Открыть адрес сайта. Сначала появится окно «Закрытый сайт»: ввести пароль на сайт. Затем страница входа с надписью IKIGAI.
2. Ввести свою почту и нажать **Получить ссылку для входа**.
3. Появится текст «Проверь почту и перейди по ссылке».
4. Открыть письмо от Supabase и нажать в нём ссылку — откроется приложение.

### Перенести записи из браузера

Если до подключения облака в приложении уже были задачи, цели и заметки, они остались
в браузере. После входа открыть **Настройки** → раздел **Облако** и нажать
**Перенести данные из браузера в облако**, затем подтвердить. Записи уедут в облако,
а копия в браузере очистится. Кнопка исчезнет — переносить больше нечего.

Там же есть кнопка **Выйти**: она завершает сеанс, данные при этом остаются в облаке.

## 5. Telegram-бот

Бот делает две вещи: принимает любые сообщения — текстом или **голосом** («купить наушники и хлеб,
в пятницу позвонить маме, 14 марта ДР Асель каждый год») — и раскладывает их по разделам приложения,
а утром присылает сводку на день. Список дел можно надиктовать одним сообщением: бот разделит его
на отдельные дела. По умолчанию он **записывает сразу** и присылает кнопку **«↩️ Отменить»**; если
хочется сначала увидеть разбор и нажать **Сохранить**, это включается в **Настройки → Telegram →
Подтверждать перед записью**.

Шаг займёт 20–30 минут. Половина из него — копирование длинных строк, поэтому лучше держать
открытым текстовый файл, куда их складывать.

### 5.1. Создать бота в Telegram

1. Открыть Telegram и найти в поиске **@BotFather** (с синей галочкой).
2. Нажать **Start** (или отправить `/start`).
3. Отправить команду `/newbot`.
4. BotFather спросит имя (**name**) — это подпись в списке чатов. Можно написать `Ikigai`.
5. Потом он спросит адрес (**username**). Адрес должен быть свободным и заканчиваться на `bot`,
   например `ikigai_dm_bot`. Если такой уже занят — придумать другой.
6. В ответ придёт сообщение со строкой вида
   `1234567890:AAH-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` — это **токен бота**.
   Скопировать его в свой текстовый файл и никому не показывать: по токену можно управлять ботом.
7. Там же в ответе есть ссылка `t.me/ikigai_dm_bot` — адрес бота. Сохранить и его.

### 5.2. Придумать два пароля

Это не пароли от чего-то существующего — их придумывают прямо сейчас, один раз.

- **TELEGRAM_WEBHOOK_SECRET** — по нему сайт проверяет, что сообщение пришло действительно
  от Telegram. Разрешены только латинские буквы, цифры, `-` и `_`, длина 10–100 знаков.
  Например: `ikigai-hook-7f3k9d2m5q8x`.
- **CRON_SECRET** — по нему проверяется утренняя рассылка (пригодится в разделе 6).
  Например: `ikigai-cron-4b7n1p6v2z`.

Оба записать в тот же текстовый файл. Придумывать что-то осмысленное не нужно —
чем длиннее и бессмысленнее, тем лучше.

### 5.3. Получить ключ ИИ

Разбором сообщений занимается Claude — за него платят по факту, копейки за сообщение.

1. Открыть <https://console.anthropic.com> и зарегистрироваться.
2. Пополнить баланс на минимальную сумму (**Billing** → **Add credits**). Без этого ключ
   не работает.
3. Открыть **API keys** → **Create Key**, дать любое имя, скопировать ключ вида
   `sk-ant-api03-...`. Он показывается один раз — сразу сохранить в текстовый файл.

### 5.3.1. Ключ для голосовых сообщений (по желанию)

Голосовые бот сначала переводит в текст. Это делает сервис Groq: бесплатно, карта не нужна.

1. Открыть <https://console.groq.com> и войти (через Google, GitHub или почту).
2. Открыть **API Keys** → **Create API Key**, дать любое имя, скопировать ключ вида `gsk_...`.
   Он показывается один раз — сразу сохранить в текстовый файл.

Без этого ключа голосовые не распознаются, но **диктовать всё равно можно**: нажать микрофон на клавиатуре
телефона, сказать список дел и отправить обычным сообщением — бот разберёт его точно так же.

> **Быстрый путь.** Шаги 5.4–5.7 делает одна команда: после того как есть токен бота (5.1) и ключ ИИ (5.3)
> (и по желанию ключ для голосовых, 5.3.1), запустить в папке проекта
>
> ```bash
> bash scripts/connect-telegram.sh
> ```
>
> Она спросит Reference ID проекта Supabase, токен и ключи (при вводе их не видно), сама придумает пароли,
> положит секреты, выложит обе функции, установит вебхук и впишет имя бота в `.env`.
> Ключи Anthropic и Groq она сразу проверяет настоящим запросом (если ключ не подошёл — спросит заново;
> если на счёте Anthropic нет денег — скажет, куда пополнить), а после выкладки стучится в функцию бота,
> чтобы убедиться, что та запущена. Один раз придётся войти в Supabase: нажать Enter, скопировать из
> браузера код подтверждения и вставить его в терминал.
> Руками остаётся только шаг 5.8 — привязать бота в настройках сайта.

### 5.4. Положить секреты в Supabase

1. Открыть проект в Supabase.
2. В левом меню внизу открыть **Project Settings** → **Edge Functions** → блок **Secrets**
   (в некоторых версиях интерфейса раздел называется **Edge Functions** → вкладка **Secrets**).
3. Кнопкой **Add new secret** добавить четыре штуки (пятую — `GROQ_API_KEY`, если нужны голосовые) — по одной, **Name** и **Value**:

   | Name | Value |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен из шага 5.1 |
   | `TELEGRAM_WEBHOOK_SECRET` | первый придуманный пароль из 5.2 |
   | `ANTHROPIC_API_KEY` | ключ `sk-ant-...` из 5.3 |
   | `CRON_SECRET` | второй придуманный пароль из 5.2 |
   | `GROQ_API_KEY` | ключ `gsk_...` из 5.3.1 (нужен только для голосовых) |

4. Нажать **Save**.

> Адрес базы и служебный ключ (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`) Supabase
> подставляет сам — добавлять их руками не нужно.

### 5.5. Выложить функции бота

Это единственный шаг, где нужен терминал. Открыть папку проекта на компьютере
(Terminal на Mac, PowerShell на Windows) и выполнить команды по одной, дожидаясь ответа.

1. Войти в Supabase из терминала:

   ```bash
   npx supabase login
   ```

   Терминал напишет `Press Enter to open browser` — нажать Enter. Откроется браузер: войти в Supabase,
   если попросит, и скопировать код подтверждения со страницы. Вернуться в терминал, вставить код
   (`Enter your verification code`) и нажать Enter — появится `You are now logged in`.

2. Узнать **Reference ID** проекта: в Supabase **Project Settings** → **General** → строка
   **Reference ID** (это же буквы из адреса `https://abcdefgh.supabase.co`).

3. Связать папку с проектом (вместо `abcdefgh` — свой Reference ID):

   ```bash
   npx supabase link --project-ref abcdefgh
   ```

   Спросит пароль базы данных — тот, что сохраняли на шаге 1.4. Если пароль потерян, его
   можно сменить в **Project Settings** → **Database** → **Reset database password**.

4. Выложить обе функции (`--use-api` — сборку делает сервер Supabase, Docker не нужен):

   ```bash
   npx supabase functions deploy telegram-webhook --no-verify-jwt --use-api
   npx supabase functions deploy cron-tick --no-verify-jwt --use-api
   ```

   В конце каждой команды должна появиться строка `Deployed Functions on project abcdefgh`.
   Проверить можно и в Supabase: **Edge Functions** — в списке появятся `telegram-webhook`
   и `cron-tick`.

### 5.6. Сказать Telegram, куда слать сообщения

Одна команда в том же терминале. В ней три подстановки: токен бота, Reference ID
и `TELEGRAM_WEBHOOK_SECRET`. Кавычки убирать нельзя.

```bash
curl "https://api.telegram.org/bot<ТОКЕН_БОТА>/setWebhook?url=https://<REFERENCE_ID>.supabase.co/functions/v1/telegram-webhook&secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```

Пример готовой команды:

```bash
curl "https://api.telegram.org/bot1234567890:AAH-xxxxx/setWebhook?url=https://abcdefgh.supabase.co/functions/v1/telegram-webhook&secret_token=ikigai-hook-7f3k9d2m5q8x"
```

В ответ должно прийти:

```json
{"ok":true,"result":true,"description":"Webhook was set"}
```

Если вместо этого написано `"ok":false` — в строке опечатка. Проверить можно командой
`curl "https://api.telegram.org/bot<ТОКЕН_БОТА>/getWebhookInfo"`: она покажет, какой адрес
записан сейчас и была ли ошибка при последней доставке.

### 5.7. Вписать имя бота в настройки сайта

1. В файле `.env` в папке проекта добавить третью строку — адрес бота **без** `@` и без `t.me/`:

   ```
   VITE_TELEGRAM_BOT=ikigai_dm_bot
   ```

2. То же самое добавить в Vercel: **Settings** → **Environment Variables** → **Add**,
   **Key** `VITE_TELEGRAM_BOT`, **Value** — тот же адрес.
3. Там же открыть **Deployments**, у верхней записи нажать меню **...** → **Redeploy**:
   переменные попадают на сайт только при новой сборке.

### 5.8. Привязать бота к себе

1. Открыть сайт, войти, открыть **Настройки** → раздел **Telegram**.
2. Нажать **Подключить Telegram**. Появится кнопка **Открыть Telegram** и надпись
   «Ссылка действует 15 минут».
3. Нажать **Открыть Telegram** — откроется чат с ботом с кнопкой **Начать** (**Start**).
   Нажать её.
4. Бот ответит: «⛩ Подключено…». В настройках сайта раздел **Telegram** теперь показывает
   «Подключено» и кнопку **Отключить**.

Если 15 минут прошли и бот отвечает «Ссылка устарела» — вернуться в настройки
и нажать **Подключить Telegram** ещё раз.

### 5.9. Проверить

Написать боту обычным сообщением: `купить наушники и в пятницу позвонить маме в 19:00`.

Через пару секунд он ответит «✅ Записал (2)» и покажет список: наушники уехали в список «Купить»,
звонок стал задачей на пятницу. Открыть сайт — записи уже там (страница обновляется сама).
Под ответом есть кнопка **↩️ Отменить**: она убирает всё, что бот только что записал.

Теперь то же голосом: зажать микрофон в чате, сказать «завтра в десять позвонить Асхату, потом купить
молоко и ещё в пятницу отправить отчёт» и отпустить. Бот напишет «🎙 Услышал: …» и запишет три дела
(для голосовых нужен ключ из 5.3.1, иначе — диктовка с клавиатуры телефона).

Если включено **Подтверждать перед записью** (Настройки → Telegram), вместо «Записал» бот присылает
«Вот что я понял:» с кнопками **✅ Сохранить**, **✏️ Изменить**, **✖️ Отмена**:

- **Сохранить** — записи появятся на сайте.
- **Изменить** — бот попросит написать, что исправить («не в пятницу, а в субботу»),
  и покажет новый разбор.
- **Отмена** — ничего не сохранится.

Чего ждать в обычной жизни:

- бот отвечает только вам; чужому человеку он напишет «Это личный бот»;
- записи появляются на сайте сразу: он слушает базу в реальном времени, перезагружать страницу не нужно;
- если ИИ недоступен или на сегодня исчерпан лимит (200 сообщений), текст не пропадёт —
  бот сохранит его заметкой во «Входящие» и честно об этом скажет;
- **Начать** и **Закончить** под задачами записывают фактическое время работы.

Если бот молчит совсем: проверить `getWebhookInfo` из шага 5.6 (там будет видно последнюю
ошибку), а затем в Supabase открыть **Edge Functions** → `telegram-webhook` → вкладка
**Logs** — в ней видно, дошёл ли запрос и на чём он споткнулся.

## 6. Напоминания по времени и утренняя сводка

Раз в минуту база сама дёргает функцию `cron-tick`. Та делает две вещи:

- **напоминания по времени.** Если у напоминания указано время (в том числе у повторяющихся, например «по будням в 10:00»),
  в эту минуту в Telegram придёт «⏰ текст». Пропустить тик не страшно: ещё 15 минут бот догоняет, но старое не поднимает;
- **утренняя сводка.** Там, где в часовом поясе человека уже наступило время сводки, бот отправляет план на день: задачи
  по времени, дела без времени, напоминания на сегодня (включая повторяющиеся и дни рождения), перенесённое
  с прошлых дней и цель недели. Под задачами — кнопки **▶ Начать**.

Всё это бесплатно: Telegram ничего не берёт, а раз в минуту — около 44 тысяч вызовов в месяц при лимите бесплатного плана
Supabase в 500 тысяч.

> **Быстрый путь.** Шаги 6.1 и 6.3 делает одна команда в папке проекта:
>
> ```bash
> bash scripts/update-bot.sh
> ```
>
> Она выложит свежий код обеих функций, сама придумает пароль для расписания (прежний при этом заменится), запишет расписание
> «раз в минуту» прямо в базу и проверит его пробным тиком. Руками остаётся только 6.2 — адрес сайта для кнопки «Открыть Ikigai»,
> он появляется после выкладки на Vercel. Эту же команду запускай после любых правок кода бота; если менялся только код,
> быстрее `CODE_ONLY=1 bash scripts/update-bot.sh` (без пароля и расписания).

Раздел 5 должен быть пройден целиком: функция `cron-tick` уже выложена на шаге 5.5,
а `CRON_SECRET` уже лежит в секретах на шаге 5.4.

### 6.1. Включить расширения базы

1. В левом меню Supabase открыть **Database** → **Extensions**.
2. В поиске набрать `pg_cron`, у найденной строки включить переключатель. Если спросит схему —
   оставить предложенную по умолчанию и нажать **Enable extension**.
3. Так же найти и включить `pg_net`.

### 6.2. Добавить адрес сайта в секреты

Он нужен для кнопки **Открыть Ikigai** под сводкой.

1. **Project Settings** → **Edge Functions** → **Secrets** → **Add new secret**.
2. **Name** — `SITE_URL`, **Value** — адрес сайта с Vercel целиком, вида
   `https://ikigai-xxxx.vercel.app`, без косой черты в конце.
3. **Save**.

### 6.3. Включить расписание

1. Открыть в папке проекта файл `supabase/migrations/0002_cron.sql` и скопировать весь текст.
2. В Supabase открыть **SQL Editor** → **New query** и вставить его.
3. Прямо в окне редактора заменить две подстановки:
   - `<PROJECT_REF>` — Reference ID проекта (те же буквы, что в адресе `https://abcdefgh.supabase.co`);
   - `<CRON_SECRET>` — второй пароль, придуманный на шаге 5.2.

   Угловые скобки тоже убрать. Должно получиться, например:

   ```sql
   url := 'https://abcdefgh.supabase.co/functions/v1/cron-tick',
   headers := '{"Content-Type": "application/json", "x-cron-secret": "ikigai-cron-4b7n1p6v2z"}'::jsonb,
   ```

4. Нажать **Run**. Внизу появится таблица с одной строкой и числом — это номер задания.
5. Проверить: выполнить в том же редакторе

   ```sql
   select jobname, schedule, active from cron.job;
   ```

   В ответе должна быть строка `ikigai-tick` · `* * * * *` · `true`.

Этот файл можно запускать повторно: старое расписание снимается перед созданием нового,
дублей не будет.

### 6.4. Проверить

Ждать до утра не нужно.

1. На сайте открыть **Настройки** → **Основное** и убедиться, что **Часовой пояс** правильный.
2. В поле **Утренняя сводка** поставить время на 5–10 минут вперёд от текущего.
3. Подождать. В течение 5–10 минут в Telegram придёт сообщение «☀️ Доброе утро…».
4. Вернуть **Утренняя сводка** на `09:00`.

Что важно знать:

- сводка за один день приходит один раз, даже если функция сработает несколько раз подряд;
- если время сводки пропущено больше чем на 2 часа (например, компьютер и телефон были
  выключены — это неважно, считает база), за сегодня она уже не придёт;
- при ошибке отправки будет ещё две попытки, потом день пропускается.

Если сообщение не пришло:

- **Edge Functions** → `cron-tick` → **Logs** — видно, вызывалась ли функция и с какой ошибкой.
  Строка `forbidden` означает, что `CRON_SECRET` в SQL и в секретах не совпадают;
- **Database** → **Cron Jobs** (или запрос
  `select * from cron.job_run_details order by start_time desc limit 10;`) — видно, запускалось ли
  задание вообще;
- запись «Подключено» в разделе **Telegram** настроек должна быть на месте: без привязки
  отправлять некуда.

## Если что-то пошло не так

- **Страница входа не появилась, приложение открылось сразу.** Переменные окружения не
  дошли до сайта. Проверить шаг 4.5, затем в Vercel открыть **Deployments** → у верхней
  записи меню **...** → **Redeploy**: переменные применяются только при новой сборке.
- **Письмо не приходит.** Проверить папку «Спам»; убедиться, что на шаге 3 включён
  **Enable Email Signup**; подождать час, если писем за сегодня было много.
- **Ссылка из письма открывает страницу с ошибкой.** Адрес сайта не совпадает с тем, что
  записан в **Redirect URLs**. Вернуться к шагу 3.7.
- **Приложение открылось пустым.** Так и должно быть: облако — это новое, отдельное
  хранилище. Записи из браузера переносятся кнопкой в разделе **Облако** настроек.
- **Наверху написано, что нет связи.** Записи не потеряются: они ждут в очереди в браузере
  и уедут в облако, как только интернет вернётся.
